# `<vt-a11y>`

`<vt-a11y>` shows accessibility test results, with violations listed by impact. Each violation comes with:

- its WCAG success criteria and level;
- the elements it was found on (selector and HTML);
- what to fix.

The checks the tool could not decide are listed apart, to review by hand.

```html
<vt-a11y variant="full" src="axe-results.json"></vt-a11y>
```

## Variants

| Feature      | `simple` (default) | `full` |
| ------------ | ------------------ | ------ |
| `header`     | off                | on     |
| `dot`        | off                | on     |
| `copy`       | off                | on     |
| `fullscreen` | off                | on     |
| `tabs`       | on                 | on     |

## Input

- **axe-core results**, from `axe.run()`, `@axe-core/playwright`, `@axe-core/puppeteer`, `cypress-axe` or the axe browser extension (exported as JSON).
- **A list of results**, one per page, as `@axe-core/cli` writes them. The rules of every page are shown together, each with its page.
- **Pa11y JSON** (`{ pageUrl, issues }`): errors are grouped by code, and the WCAG criterion and level are read from the code.

Up to 500 rules and 200 elements per rule are read.

## Results

- **Summary**: the failed rules and the elements they were found on, the rules passed and those not applicable, the page, the version of axe-core, and the counts by impact (critical, serious, moderate, minor).
- **Violations**: the most severe first, then the rules found on the most elements. Each rule shows:
  - its impact in words, its help text and its identifier;
  - its WCAG criteria (`1.4.3`) and level, read from axe's tags, or "best practice" when it is not a WCAG requirement;
  - the number of elements, and a "Learn more" link to Deque University.

  The first five elements are listed, with their selector and HTML snippet. Frames are joined with `→` and shadow roots with `>>>`. Each element has its fixes, as axe groups them ("Fix any of the following:", "Fix all of the following:"). A button shows the other elements.

- **To review**: the incomplete checks, such as contrast over a background image. axe could not decide them, so they need a person.

Automated tools find only part of the problems. With no violation, the element says so and recommends testing with a keyboard and a screen reader too.

With `filters` (on by default), there is a button per impact and a field. The field keeps the rules whose identifier, help text, criterion or selector contains a text.

## Attributes

| Attribute | Values                 | Default      | Description                        |
| --------- | ---------------------- | ------------ | ---------------------------------- |
| `view`    | `violations`, `review` | `violations` | Tab shown first.                   |
| `filters` | boolean                | on           | Impact and text filters.           |
| `tabs`    | boolean                | on           | The Violations and To review tabs. |

The shared attributes (`variant`, `theme`, `src`, `label`, `copy`, `mode`…) are described in [common attributes](../common-attributes.md).

## Copy

| Button             | Output                                                                                                                                |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| CSV                | `rule,impact,wcag,page,target,html`, one row per element of the rules shown. Cells a spreadsheet would run as a formula are prefixed. |
| Copy the selectors | The selectors of the elements of the rules shown, one per line.                                                                       |

## Properties

| Property  | Type             | Description                                                                                                                                                                                                                                                              |
| --------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `content` | `string`         | The results (JSON).                                                                                                                                                                                                                                                      |
| `results` | `object \| null` | Read-only. It has the form `{ pages, engine, timestamp, violations, incomplete, passes, inapplicable, capped }`. Each rule is `{ id, impact, help, description, helpUrl, criteria, level, tags, nodes, total, page }`. Each node is `{ target, html, summary, impact }`. |

## Events

| Event              | Detail                      | When                                 |
| ------------------ | --------------------------- | ------------------------------------ |
| `vt-ready`         | `{ type: "a11y" }`          | The results are rendered.            |
| `vt-tab-change`    | `{ tab }`                   | The tab changed.                     |
| `vt-filter-change` | `{ impacts, query, shown }` | The filters changed.                 |
| `vt-copy`          | `{ text }`                  | CSV or selectors copied.             |
| `vt-error`         | `{ message, cause }`        | Loading failed or content too large. |

## CSS parts

| Part      | Element                  |
| --------- | ------------------------ |
| `summary` | The summary.             |
| `filters` | The filters.             |
| `rule`    | A rule and its elements. |
| `impact`  | An impact badge.         |
| `node`    | An element.              |

## Accessibility

Each rule is a section named after its help text, and its elements are an ordered list. The selector and the HTML are announced as such. Impacts are words; colors and border widths only repeat them. Filters are toggle buttons.

## Security

HTML snippets from the results are shown as text, never parsed. Help links are made only for absolute `http(s)` URLs, with `rel="noopener noreferrer"`. CSV cells that could run as formulas are prefixed.
